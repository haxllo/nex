Change hotkey at runtime — no restart needed. Win key chord detection fixed so Win+ shortcuts work natively. Dynamic re-registration stable (11 bugs resolved).

### Features

- **Change hotkey at runtime**: edit `config.toml` while nex is running — new hotkey applies instantly, no restart required
- **Win+ chords work natively**: Win+E opens Explorer, Win+R opens Run while Nex is active — chord keys pass through the hook

### Bug Fixes

- **Win key chord detection**: fire hotkey on key-up only, chord keys (E, D, R, etc.) pass through — Win+E opens Explorer, Win+R opens Run
- **Win+ chords blocked**: hook no longer eats Win key-down; `GetAsyncKeyState` stays accurate, keyboard state clean after hide
- **Helper key-up mismatch**: removed WM_INPUT Win toggle; both nex and helper fire on key-up, no double-toggle on second press
- **Dynamic hotkey change stability (11 bugs fixed)**: no freeze, no deadlock, no spurious toggles, no zombie threads during re-registration
- **Quick launch pop-in**: first show bypasses resize debounce, removed full-DB pre-read — content appears in single frame
- **Launch flash**: hide overlay synchronously before ShellExecuteW so launched app gets foreground

### Architecture

- **HotkeyListener::start_no_helper()**: re-registration skips helper spawn, in-process hook installed within ~1s (was up to 120s pipe retry)
- **connect_pipe retries reduced**: 40 → 10 (~8s max wait vs ~120s)
