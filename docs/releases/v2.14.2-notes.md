Quick hotfix release: accent color now matches the Windows accent exactly in both automatic and custom modes (byte-order decode fix), and the pinned bookmark icon renders as a vibrant solid accent fill.

## User-Reported Issues (checklist — completes step 2)

- [x] Wrong accent color shown when accent set to Automatic → fixed: accent DWORDs decoded as RGBA (was ABGR — swapped red/blue into a complementary hue); primary source is `Explorer\Accent\StartColorMenu`, which tracks both custom picks and auto-derived accents
- [x] Accent color looked dull on pinned bookmark icon → fixed: icon is now a solid accent fill instead of a thin 1.5px stroked outline

## Changelog (3 commits since v2.14.1)

### Bug Fixes

- **Accent color mismatch**: registry accent DWORDs (`AccentColor`, `StartColorMenu`) are stored in RGBA byte order; the old ABGR decode swapped red/blue and rendered the complementary hue (e.g. orange for a blue accent). Decode corrected, verified against the `AccentPalette` ramp and `DwmGetColorizationColor` readings.
- **Accent detection source**: accent now reads from `Explorer\Accent\StartColorMenu` (always live — custom picks and automatic/wallpaper-derived accents), falling back to the DWM `AccentColor` value, then `DwmGetColorizationColor`. Diagnostic log line added (`[nex] accent detect: ...`).

### Features

- **Pinned bookmark icon**: solid accent-colored fill (was a thin stroked outline that read muted on the dark surface).
