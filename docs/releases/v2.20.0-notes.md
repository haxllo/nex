## Web bookmarks and Quick Launch overhaul

The main addition is web bookmarks. Save any URL, see its favicon, open it in your browser, and pin it to Quick Launch like any app. We also fixed context menus (they used to clip, dismiss randomly, or show the browser's built-in menu instead of ours) and made search results cleaner by deduplicating before display.

## What changed

- Web bookmarks are now first-class results with favicons, context actions, and Quick Launch pinning.
- Context menus stay within the viewport, size correctly, dismiss on keyboard input, and no longer fight with Chromium's native right-click menu.
- Search results are deduplicated before the limit is applied, so duplicates no longer crowd out other matches.
- Websites pinned to Quick Launch now show their title, share favicons with search, and handle legacy pins from earlier versions cleanly.

### Features

- Save and manage URLs as persistent bookmarks with local storage.
- Right-click bookmarks for actions like open, pin, and remove.
- Bounded favicon cache displays website icons next to bookmark results.
- Bookmark results open directly in your default browser.
- Website results display favicons in search.
- Configuration is now fully TOML-based. JSON/JSON5 backward compatibility is preserved but no longer the default.

### Bug Fixes

- Context menus no longer clip at overlay edges or fight with Chromium's native menu.
- Menus reposition themselves to stay fully visible and dismiss reliably on Escape or typing.
- Bookmark context menus size correctly and appear above the result row when there's no space below.
- Pinned websites show their title instead of a raw URL.
- Legacy Quick Launch pins from earlier versions are removed cleanly without errors.
- Settings entries pin and unpin correctly from Quick Launch. The settings menu closes when you start typing.
- Duplicate results are removed before the result limit is applied.
- Uninstall entries wrapped by Windows no longer appear as separate results.
- Direct URL matches rank above fuzzy search results.
- Search and Quick Launch share a single favicon cache instead of each maintaining their own.
- Favicon requests for direct URLs are validated before fetching.
- Bookmarks with embedded credentials (user:pass@host) are rejected.
- The search index refreshes properly after a full replacement. Launch frequency data survives index rebuilds.
- Website results preserve their metadata (URL, title, favicon) across sessions.
