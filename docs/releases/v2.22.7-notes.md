## Updates that land in the right place

Hitting update used to fail with "already installed for all users" even though the install lived in the per-user folder. The updater now figures out which copy is actually running — yours or the machine-wide one — and silently updates exactly that, cleaning up a stale duplicate registration instead of giving up.

## What changed

- **Right copy, silently**: The updater detects whether your install is per-user or machine-wide (from where it's actually running) and updates that path with no wizard prompts.
- **No more phantom "all users" error**: A leftover machine-wide registration pointing at a per-user folder used to block every update and every manual setup run. That stale entry is now removed automatically during the update instead of aborting it.
- **Genuine conflicts still stop**: If there really is a separate machine-wide install under Program Files, setup still asks you to rerun as All users or uninstall that copy first — that message now only appears when it's actually true.

### Bug Fixes

- **Update failed after "updating"**: Fixed the scope mismatch where the updater launched a per-user install over a stale machine-wide registration and the installer refused it at the end.
- **Manual setup hit the same wall**: The downloaded setup hit the identical error for the same reason; it now cleans the stale entry when elevated instead of failing.
