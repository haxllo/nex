## Nex now indexes in its own process

The work of watching your folders and keeping the search index current moved
out of the window process into a separate background process. Nex opens and
searches like before, but typing never waits on indexing, and a stuck or
restarting indexer no longer takes the launcher with it. This release also
fixes new files under a drive root being missed, stops indexing build output,
and removes a faint shadow rectangle that appeared at startup.

## What changed

### Process isolation

- **Indexing runs separately**: `NexUIProcess.exe` owns the overlay, hotkeys,
  tray, and search; `NexIndexerProcess.exe` owns folder discovery, the
  database, the file watchers, and the search index. The two talk over a
  local socket.
- **Quitting stops everything**: the indexer now exits with Nex instead of
  lingering in Task Manager holding the index files.
- **Crash tolerance**: if the indexer stops, Nex keeps serving the last
  snapshot and starts it again; if the UI closes, the indexer exits on its
  own.
- **Clear names in Task Manager**: `NexUIProcess`, `NexIndexer`, and
  `NexAdminAccess` instead of several identical "Nex" entries.

### Search & indexing

- **New files under a drive root**: creating a file under `G:\` (or any
  configured drive root) while Nex was running never reached search. Fixed;
  new files appear within seconds.
- **Build output is skipped**: `node_modules`, `target`, `dist`, `build`,
  `coverage`, `.zig-cache`, `obj`, CMake, Terraform, and similar folders are
  no longer indexed, so they stop consuming the index budget. Suffixed names
  such as `.node_modules.staging-*` are covered too.
- **Cheaper updates**: the indexer now sends only what changed instead of the
  whole item list, serves snapshots from memory instead of rescanning the
  database, and the UI keeps its prefix cache between updates.
- **UI writes go through the indexer**: launch history, selections, and
  recent documents are written by the process that owns the database.
- **Faster first open**: the UI no longer loads every row from disk before
  the hotkey is ready.
- **Diagnostics**: the indexer now writes to `%APPDATA%\Nex\logs\nex.log`,
  including watcher and rescan activity.

### Overlay

- **Startup ghost**: a transparent, panel-sized rectangle with a shadow was
  visible at the top-left after launch until Nex was opened once. The window
  is now cloaked from creation, so only an explicit show can draw it.
- **Clicking Task Manager closes Nex**: clicking an elevated window behind
  the panel now hides it, including the first click after startup.
- **First keystroke**: the search field owns focus before the panel appears,
  so the first character is no longer missed in compact view.

## Notes

- The indexer is a second process by design. If Task Manager is missing it,
  Nex still searches the last snapshot and restarts it.
- If you index a whole drive, the log may report a per-root item cap; raise
  `index_max_items_per_root` (and `index_max_items_total`) to index more.

## Upgrade Notes

- **Updating from 2.37.0 works in place**: this release ships a small
  `Nex.exe` forwarding launcher only so the 2.37.0 updater can finish and
  restart the new UI process. `NexUIProcess.exe` is the real entry point from
  now on; the launcher is removed in the next release.
- The first launch after updating rescans your folders once because the
  exclusion rules changed. Search keeps working from the existing index while
  that runs.
