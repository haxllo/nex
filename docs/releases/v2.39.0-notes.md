## Indexing now reads the NTFS MFT

Nex no longer has to walk every folder to find your files. On NTFS drives it
reads the Master File Table directly — a sequential metadata pass instead of
tens of thousands of directory lookups — and the scan runs at background
priority so the desktop stays responsive. Non-NTFS volumes and systems
without the elevated helper keep the old folder walk as a fallback.

## What changed

### Search & indexing

- **NTFS MFT discovery**: the helper process (already elevated for hotkeys)
  serves a read-only per-volume snapshot of the MFT; the indexer rebuilds
  paths from file-reference/parent pairs and applies your roots, exclusions,
  depth, and item caps as before.
- **Walkdir is now the fallback**, not the primary path. It still covers
  exFAT/network volumes, locked BitLocker volumes, and runs without the
  helper (portable or before the scheduled task exists).
- **Background priority**: the index cycle runs below normal with Windows
  background I/O priority, so a startup scan cannot starve the desktop or the
  first overlay show.
- **Measured on this machine** (40k per-root cap): C: reads 1.13M MFT records
  in ~16 s, G: (HDD) 718k in ~45 s; the indexer keeps the 40k shallowest
  entries per root exactly as before.

### Notes

- A full MFT pass still happens once per session while a drive is re-read;
  the next step is replaying the NTFS change journal (USN) so later starts
  only apply what changed.
- If the helper is unavailable, Nex waits briefly, then uses the folder walk
  for the rest of the cycle.
- `NEX_DISCOVERY_BACKEND=walkdir` forces the old path; `mft` forces the new
  one (useful when diagnosing).

## Upgrade Notes

- Updating from 2.37.0 or 2.38.x works in place. The temporary `bin\Nex.exe`
  launcher is still shipped for 2.37.0 installs and stays inert elsewhere.
- The elevated helper's scheduled task is unchanged; first launch on a fresh
  profile still prompts once to create it.
