## Nex is now two processes, and search keeps up with big indexes

Nex no longer does indexing inside the window you type into. A separate
`NexIndexerProcess` owns discovery, SQLite, and the search index; the UI
process only renders and queries a published snapshot. That keeps the overlay
responsive while large drives are scanned, and it lets the indexer keep
running in the background after you close the window.

Search itself was rebuilt for scale: batched SQLite writes, a bounded
in-memory cache, an exact candidate index, and parallel scanning, so queries
stay fast as the index grows. MFT-based discovery now applies USN deltas
instead of re-scanning whole volumes, and renamed or deleted subtrees are
reconciled automatically. A disk-backed icon cache (validated by file
size/mtime) survives restarts.

## What changed

### Architecture

- **Process split**: `NexUIProcess.exe` (overlay, hotkeys, tray, search) and
  `NexIndexerProcess.exe` (discovery, SQLite, Tantivy) are separate binaries
  with distinct Task Manager names. The UI spawns and supervises the indexer;
  the indexer exits when the UI goes away.
- **No `Nex.exe`**: the legacy launcher and in-process indexing fallback are
  gone. The UI always talks to the indexer over IPC.
- **Helper stays elevated**: `NexHelper.exe` remains the privileged broker for
  hotkey detection and MFT snapshots; it never owns process lifecycle.

### Search & indexing

- **Batched rebuilds**: SQLite writes and Tantivy updates happen per batch,
  with point lookups instead of full store maps.
- **Bounded cache**: the UI keeps only the hot set; the first snapshot is
  built from SQLite.
- **USN deltas**: changed files are applied incrementally; a full pass runs
  when a volume has no saved journal position.
- **MFT deltas**: directory creates, renames, and deletes are reconciled,
  including deletes propagated to Tantivy.
- **Parallel scan**: the search index is scanned in parallel.
- **Live results**: the visible query re-runs when the index changes.
- **Progress window**: a non-activating progress window appears during large
  full passes.

### Icons

- **Disk-backed cache**: decoded icons are cached on disk (size/mtime
  fingerprinted) and survive restarts; "Clear Icon Cache" empties both tiers.

### UI

- **Graphite palette**: monochrome redesign of the overlay and Settings.
- **Settings refresh**: dropdowns, keycaps, compact indexing note, discovery
  roots editor, live status and removal state.
- **Footer simplification** and empty-state polish.

### Notes

- Updating from 2.39.x works in place. The installer still removes leftover
  `Nex.exe` files from older installs.
- The elevated helper's scheduled task is unchanged; first launch on a fresh
  profile still prompts once to create it.
- `NEX_DISCOVERY_BACKEND=walkdir` still forces the folder walk; `mft` forces
  MFT discovery.
